# Rech для VS Code

Полноценная поддержка языка [Rech](https://github.com/IlyaFeoktistov/Rech) в
VS Code: подсветка синтаксиса, автодополнение и hover, переход к
определению/реализации, поиск ссылок, сборка/запуск/тесты одной кнопкой,
автоформатирование и полноценный отладчик с точками останова.

## Возможности

### Редактирование

- Подсветка синтаксиса `.rech`-файлов.
- Hover - наведение на имя показывает его сигнатуру, тип и документацию
  (в т. ч. текущее значение константы).
- Автодополнение после `.` - поля, методы, встроенные функции.
- Переход к определению и к реализации интерфейса.
- Поиск ссылок и подсветка вхождений выделенного слова по всему документу.
- Code Lens - кликабельное "N ссылок" над каждым объявлением.
- Быстрые исправления - автоимпорт нужного объявления, авто-сокращение
  вроде `i = i + 1` → `i++`, предложение сделать метод статическим, если
  он не обращается к экземпляру, и т. п.
- Диагностика по мере набора текста - ошибки и предупреждения
  подчёркиваются сразу, без запуска сборки.
- Автоформатирование при сохранении файла (канонический отступ, стиль
  скобок, выравнивание полей и переменных в таблицу) - включено из
  коробки.

### Команды

Доступны через палитру команд (`Ctrl+Shift+P` / `Cmd+Shift+P`) и через
кнопки в заголовке редактора для открытого `.rech`-файла:

| Команда | Действие |
|---|---|
| **Rech: собрать** | Собирает цель, ошибки показываются прямо в редакторе |
| **Rech: собрать библиотеку** | Собирает разделяемую библиотеку (`.so`/`.dylib`/`.dll`) + C-заголовок |
| **Rech: собрать и запустить** | Собирает и запускает в интегрированном терминале (с настоящим stdin/stdout) |
| **Rech: отладить** | Запускает отладчик на той же цели |
| **Rech: запустить тесты** | Прогоняет тесты по рабочей области |

Целью команды становится файл проекта (`*.rechproj`) в корне рабочей
области, если он там один; иначе - активный `.rech`-файл редактора.

### Отладка

Точки останова, продолжить / шаг через / шаг внутрь / шаг наружу, стек
вызовов, просмотр локальных переменных и полей сущностей, Debug Console с
вычислением произвольных Rech-выражений в контексте остановленного кадра.
Отдельные потоки, запущенные через `запустить`, видны в панели вызовов
наравне с главным потоком.

Запускается кнопкой/командой **Rech: отладить** без всякой настройки, либо
через `launch.json`, если нужен конкретный файл или флаг `stopOnEntry`:

```json
{
  "type": "rech",
  "request": "launch",
  "name": "Rech: отладить",
  "program": "${file}",
  "stopOnEntry": false
}
```

## Требования

Нужен установленный компилятор `rech` (см. [репозиторий
языка](https://github.com/IlyaFeoktistov/Rech)) - либо в `PATH`, либо путь
к нему указан в настройке `rech.path`.

## Настройки

| Настройка | По умолчанию | Описание |
|---|---|---|
| `rech.path` | `rech` | Путь к исполняемому файлу компилятора, если он не в `PATH` |
| `rech.format.enable` | `true` | Форматирование документа (команда и автосохранение) |
| `rech.format.maxLineLength` | `120` | Зарезервировано на будущее (перенос длинных строк пока не реализован) |
| `rech.lsp.enable` | `true` | Языковой сервер целиком (hover/автодополнение/диагностика и т. п.) - выключить, если нужны только сборка/запуск/форматирование |
| `rech.lsp.trace.server` | `off` | Трассировка протокола языкового сервера (`off`/`messages`/`verbose`), для отладки |

Расширение также включает для `.rech`-файлов отступ пробелами (не табами,
4 пробела на уровень) и автоформатирование при сохранении - без ручной
настройки.

## Установка

Расширение пока не опубликовано в Marketplace - устанавливается локально,
`.vsix`-файлом. Подробные шаги (сборка компилятора, упаковка и установка
расширения) - в [DEVELOPMENT.md](DEVELOPMENT.md).

## Известные ограничения

- Диагностика ошибок сборки (не LSP) ставится на текущий открытый файл,
  даже если сама ошибка - в файле, импортированном через `использовать`.
- Поиск ссылок для `receiver.поле`/`receiver.метод()` пока не поддержан -
  только голое имя (переменная, функция, сущность, константа модуля).
