# Rech для VS Code

Расширение VS Code для языка [Rech](https://github.com/IlyaFeoktistov/Rech):
подсветка синтаксиса `.rech`-файлов, команды сборки/запуска/тестов и
полноценный отладчик (точки останова, пошаговое исполнение, просмотр
переменных, Debug Console).

Автор: Ilya Feoktistov.

## Возможности

- Подсветка синтаксиса (`syntaxes/rech.tmLanguage.json` - TextMate-грамматика,
  см. "Грамматика" ниже).
- Настройки языка: комментарий `//`, автозакрытие `{}`/`()`/`"..."`.
- **Цель команд** ("что собрать/запустить/отладить") - файл проекта
  (`*.rechproj`) в корне рабочей области, если он там ровно один (как и
  `rech build`/`rech run` сами выбирают цель без явного пути); иначе -
  активный `.rech`-файл редактора.
- Команды (палитра команд, `Ctrl+Shift+P`/`Cmd+Shift+P`, и кнопки в
  заголовке редактора для открытого `.rech`-файла):
  - **Rech: собрать** - `rech build <цель>`, вывод и ошибки - в панели
    "Rech" (Output), ошибки вида "строка N: ..." подчёркиваются прямо в
    редакторе на нужной строке.
  - **Rech: собрать библиотеку** - `rech build --lib <цель>` (docs/
    ROADMAP.md, Шаг 7, "обратное направление") - разделяемая библиотека
    (`.so`/`.dylib`/`.dll`) и C-заголовок (`.h`) из объявлений, помеченных
    `экспортировать`, вместо обычного бинарника. Своей команды запуска нет
    - библиотека не исполняется как программа.
  - **Rech: собрать и запустить** - `rech run <цель>` в интегрированном
    терминале (не в фоне) - в отличие от "собрать", у выполняемой
    программы может быть свой интерактивный ввод (`прочитать_строку` и
    т. п.), терминал даёт настоящий stdin/stdout.
  - **Rech: отладить** - запускает отладчик (см. "Отладка" ниже) на той же
    цели, без необходимости заводить `launch.json`.
  - **Rech: запустить тесты** - `rech test <корень рабочей области>`.
- **Форматирование** (`rech fmt` - канонический отступ, docs/ROADMAP.md
  проекта Rech, Шаг 89) - команда "Format Document" и автоматически при
  сохранении, если включена штатная настройка VS Code `editor.formatOnSave`
  (не своя). Отключается настройкой `rech.format.enable`. Перенос длинных
  строк (`rech.format.maxLineLength`) - зарезервировано на будущее, сам
  компилятор пока умеет только отступ, ничего не переносит.
- Настройка `rech.path` (Settings) - путь к исполняемому файлу `rech`, если
  он не в `PATH`.

## Отладка

Точки останова (клик слева от номера строки), продолжить/шаг через/шаг
внутрь/шаг наружу, стек вызовов, просмотр локальных переменных и полей
сущностей (разворачиваются по клику), Debug Console - вычисление
произвольных Rech-выражений в контексте остановленного кадра. Отдельный
поток на каждую задачу, запущенную через `запустить` (docs/ROADMAP.md, шаг
15) - виден в панели "CALL STACK" наравне с главным потоком.

Запускается либо кнопкой/командой **Rech: отладить** (без всякой настройки -
цель та же, что и у "собрать"/"запустить"), либо через `launch.json`
(`F5`/панель "Run and Debug"), если нужен `stopOnEntry` или явный
конкретный файл:

```json
{
  "type": "rech",
  "request": "launch",
  "name": "Rech: отладить",
  "program": "${file}",
  "stopOnEntry": false
}
```

Отладчик целиком реализован в самом компиляторе (`rech debug` - сервер
[Debug Adapter Protocol](https://microsoft.github.io/debug-adapter-protocol/)
по stdin/stdout, `internal/debugadapter`/`internal/interp.Debugger`) -
расширение только запускает этот процесс, никакой логики отладки в JS нет.
Исполнение идёт через интерпретатор Rech (`internal/interp`), не через
`gdb`/`lldb` на скомпилированной программе - отсюда одно известное
ограничение: стандартный ввод отлаживаемой программы
(`прочитать_строку`/`прочитать_целое`/`прочитать_число`) не подключён к
интерактивному вводу в этом срезе (сам `stdin` процесса `rech debug` занят
протоколом DAP) - такой вызов под отладчиком сразу получает конец ввода.

## Установка

Расширение пока не опубликовано в Marketplace - устанавливается локально,
`.vsix`-файлом. Нужны три вещи по порядку: сам компилятор `rech`, пакет
расширения, и (если `rech` не в `PATH`) настройка, где его искать.

### 1. Собрать компилятор `rech`

Расширение только вызывает уже готовый `rech` - само его не устанавливает
и не собирает. Нужен Go (для сборки самого компилятора) и системный
C-компилятор (`cc`/`clang`/`gcc` в `PATH`, либо переменная `CC`) - его уже
требует сам `rech`, см. [README основного репозитория](https://github.com/IlyaFeoktistov/Rech).

```sh
git clone https://github.com/IlyaFeoktistov/Rech.git
cd Rech
go build -o rech ./cmd/rech
```

Получится исполняемый файл `rech` (на Windows - `rech.exe`) в корне
клонированного репозитория. Дальше либо положите его в `PATH` (например,
`mv rech ~/go/bin/` или любой другой каталог из `PATH`), либо оставьте на
месте и укажите полный путь в настройке `rech.path` расширения (шаг 3) -
класть в `PATH` не обязательно.

### 2. Собрать и установить расширение

Нужны Node.js и `npm` (для однократной сборки `.vsix` - самому расширению
во время работы Node не нужен, оно исполняется движком расширений VS
Code). `@vscode/vsce` ставить глобально не нужно - `npx` скачает его во
временный кэш на одно использование:

```sh
git clone https://github.com/IlyaFeoktistov/rech-vscode.git
cd rech-vscode
npx --yes @vscode/vsce package
code --install-extension rech-0.1.0.vsix
```

(`code` - CLI VS Code; если команда не найдена, добавьте её в `PATH` через
VS Code: `Ctrl+Shift+P` -> "Shell Command: Install 'code' command in PATH".)

Перезагрузите окно VS Code (`Ctrl+Shift+P` -> "Reload Window"), если оно
было открыто во время установки - иначе расширение не активируется.

### 3. Проверить, что всё работает

Откройте любой `.rech`-файл (например, `examples/пример.rech` из этого
репозитория) - должна появиться подсветка. Затем `Ctrl+Shift+P` -> "Rech:
собрать" (или кнопка ⚙ в заголовке редактора). Если появляется ошибка "не
удалось запустить rech" - `rech` не найден ни в `PATH`, ни по пути из
настройки `rech.path`: откройте настройки (`Ctrl+,`), найдите `rech.path`
и впишите туда полный путь к бинарнику из шага 1 (например,
`/home/имя/Rech/rech` или `C:\Users\имя\Rech\rech.exe`).

## Разработка

Расширение - обычный JS без шага сборки (без TypeScript/webpack) -
достаточно открыть эту папку в VS Code и нажать F5 (конфигурация "Запустить
расширение Rech" уже в `.vscode/launch.json`) - откроется новое окно VS
Code с загруженным расширением, без пересборки `.vsix` на каждое
изменение. Примеры для проверки - в `examples/`.

После правок в `extension.js`/`package.json`/грамматике, чтобы обновить
уже установленную (не через F5) копию - пересобрать `.vsix` и переустановить
той же командой, что и в шаге 2 (`code --install-extension` перезапишет
предыдущую версию).

## Грамматика

`syntaxes/rech.tmLanguage.json` (`.tmLanguage.json`, scope `source.rech`) -
TextMate-грамматика, независимая от VS Code по формату: понимают также
Sublime Text, TextMate, IntelliJ (через bridge) и GitHub Linguist - файл
можно взять и использовать напрямую в любом из них, не только через это
расширение. `language-configuration.json` рядом - комментарии (`//`),
автозакрытие скобок и кавычек (общие настройки редактора, не подсветка).
`examples/` - примеры на Rech для визуальной проверки подсветки; все реально
компилируются и запускаются через `rech run` (сверено с [основным
репозиторием](https://github.com/IlyaFeoktistov/Rech)).

Покрывает актуальный синтаксис v0.1: комментарии, строки, числа, `истина`/
`ложь`, управляющие конструкции (`если`/`иначе`/`пока`/`для`/`вернуть`/
`утверждать`/`становится`/`выбрать`/`когда`/`попытаться`/`поймать`/
`выбросить`/`относится`), словесные логические операторы (`и`/`или`/
`не`), объявления (`функция`/`сущность`/`класс`/`структура`/`перечисление`/
`константа`/`имеет`/`состояние`/`использовать`/`внешняя`/`экспортировать`,
включая имена в списке `использовать <имя>, <имя> ... из`), модификаторы
видимости (`приватный`/`публичный`/`абстрактный`, все родовые формы),
конструктор (`новый`/`новая`/`новое`/`новые`), встроенные типы (`Строка`/
`Целое`/`Число`/`Логическое`/`Файл`/`Список`/`Стопка`/`Очередь`/`Словарь`/
`Тип`/`Значение`), тег поля/метода/сущности (`` `ключ:значение` `` после
объявления), разбор и сборка JSON/XML (`разобрать JSON/XML <выражение> как
<Тип>`, `сериализовать JSON/XML <выражение>`, `ОшибкаРазбора`), изоляция
паники (`поймать (x: Паника)`), статический доступ (`Тип::имя`), константы
(отдельно от типов и обычных полей/методов, в т. ч. голой ссылкой в теле
функции), имена типов (заглавная буква), вызовы функций и методов,
операторы (включая составное присваивание `+=`/`-=`/`*=`/`/=`/`%=`,
остаток `%`, nullable `?Тип`/`??`/`?=`). Нормативное описание синтаксиса -
[docs/SPEC.md в основном
репозитории](https://github.com/IlyaFeoktistov/Rech/blob/master/docs/SPEC.md);
последовательное руководство -
[docs/MANUAL.md](https://github.com/IlyaFeoktistov/Rech/blob/master/docs/MANUAL.md).

Не покрывает (пока не реализовано в языке): естественное падежное
согласование самой грамматикой (подсветка не различает падежи - это работа
компилятора/LSP, не подсветки синтаксиса), generic-параметры произвольной
глубины, всё из
[docs/ROADMAP.md](https://github.com/IlyaFeoktistov/Rech/blob/master/docs/ROADMAP.md).

## Известные ограничения этого среза

- Диагностика ошибок - разбор текста ошибки компилятора по шаблону
  "строка N: ...", не настоящий LSP - если ошибка на самом деле в другом
  файле (например, импортированном через `использовать`), диагностика всё
  равно ставится на текущий открытый файл (лучшее, что можно сделать без
  языкового сервера).
- LSP-сервер (`rech lsp`, internal/lsp в основном репозитории) есть и
  реализует hover, go-to-definition, go-to-implementation, автодополнение,
  code actions (автоимпорт), code lens, find-references и
  document-highlight ("подсветить все вхождения выделенного слова"),
  диагностику по мере набора текста (в т. ч. по нескольким файлам через
  `использовать` - см. multifile.go). References/document-highlight - ТОЛЬКО
  в пределах текущего открытого документа (не по всему проекту) и ТОЛЬКО для
  голого имени (локальная переменная/параметр, функция, сущность, константа
  модуля) - `receiver.поле`/`receiver.метод()` пока не поддержаны (потребовало
  бы вывода типов для каждого такого обращения во всём файле). У переменной
  вхождением считается и её падежная словоформа ("паролем" - ссылка на
  переменную "пароль"), не только буквальное совпадение текста - то, что
  встроенная в VS Code подсветка "одинаковых слов" сама по себе не умеет.
  Остальные пробелы - см.
  [docs/ROADMAP.md](https://github.com/IlyaFeoktistov/Rech/blob/master/docs/ROADMAP.md),
  раздел "Инструментарий вокруг языка".
